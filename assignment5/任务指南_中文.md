# A5：用户类的复制与运算符

这是根据起始代码与任务要求编写的原创中文任务指南，不是逐段译本。完整要求见[英文原文](README.md)。

## 目标与修改范围

`User` 用动态字符串数组保存好友。练习让对象正确管理这块内存，并支持自然的打印、比较与互加好友操作。修改并交付 `user.h` 和 `user.cpp`。

## 接口清单

以下是需要补充的接口，不是实现代码：

| 接口 | 要求 |
| --- | --- |
| `std::ostream& operator<<(std::ostream&, const User&)` | 非成员友元函数；在头文件声明，在源文件定义。 |
| `~User()` | 释放对象拥有的好友数组。 |
| `User(const User&)` | 复制构造，复制后的数组相互独立。 |
| `User& operator=(const User&)` | 复制赋值，正确处理原有资源并返回自身引用。 |
| `User(User&&)` | 显式删除移动构造。 |
| `User& operator=(User&&)` | 显式删除移动赋值。 |
| `User& operator+=(User& rhs)` | 成员函数；双方互加好友，返回左侧对象的引用。 |
| `bool operator<(const User& rhs) const` | 成员函数；按姓名的字符串顺序比较。 |

## 关键验收

- 打印格式严格为 `User(name=姓名, friends=[好友1, 好友2])`，空列表为 `[]`，函数自身不追加换行。
- 复制后修改一个对象的好友，另一个对象不应变化。`_name`、`_size` 和 `_capacity` 也应保持正确。
- 赋值不能泄漏旧数组，销毁不同副本不能重复释放同一块内存。建议另测自我赋值。
- 双方互加后，各自列表中都有对方姓名。

已有构造函数及 `add_friend` 等辅助成员位于 `user.cpp`。先读懂 `_size` 与 `_capacity` 的差别，再补充接口；不要改变测试文件来绕过要求。
